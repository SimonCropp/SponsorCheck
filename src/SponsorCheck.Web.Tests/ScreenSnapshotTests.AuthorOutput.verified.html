1. Reference SponsorCheck

Add SponsorCheck as a PrivateAssets="all" development dependency (element(s) below go inside an <ItemGroup>; multi-file snippets name the target file in a comment):

PackageReference (library .csproj) 
<PackageReference Include="SponsorCheck" Version="9.9.9" PrivateAssets="all"
                  GitHubSponsorsAccount="acmecorp"
                  SponsorOwner="acme" />
<SponsorExemption Include="Consulting"
                  Message="Consulting clients are exempt for 6 months." />

Supply each platform's API token. Precedence is MSBuild property → env var → user-secret:

Credential setup 
# Local dev — store tokens outside the repo with user-secrets.
# Run from the directory containing the library .csproj:
dotnet user-secrets init
dotnet user-secrets set "SponsorCheck:GitHubToken" "<token>"   # required

# CI — expose each token as an environment variable of the SAME name
# (MSBuild auto-imports it as the matching <...Token> property; GITHUB_TOKEN does NOT auto-flow):
GitHubToken   # required

# Pull-request CI builds: providers withhold encrypted secrets, so bundling is skipped
# (the package packs without the verifier and a build message records it). To force
# bundling on PR builds that do have the credential, set the MSBuild property:
#   <SponsorCheckBundleInPullRequest>true</SponsorCheckBundleInPullRequest>

# Token notes:
# - GitHub Sponsors: Required. Create a classic PAT (https://github.com/settings/tokens/new) with read:user, plus read:org if sponsored as an organization. Fine-grained PATs have no Sponsorships permission, so a classic PAT is the only option. The token must be owned by the sponsored account (or an admin of the sponsored org) — otherwise private sponsors are silently missing from the bundled list.

2. Tell your consumers

Paste this markdown into the release notes / changelog for the version that adds SponsorCheck:

Release notes (markdown) 
## Sponsorship is now checked at build time

`MyOssLib` 2.0.0 now bundles [SponsorCheck](https://github.com/SimonCropp/SponsorCheck) — a build-time check that asks teams using this package to sponsor its ongoing development. SponsorCheck adds **no runtime dependency**; the check runs only during the build.

After upgrading, every build looks for one of the options below. If none is configured the build fails with an error.

### What you need to do

This package uses **owner mode**, so you configure sponsorship **once** as a global MSBuild property (in `Directory.Build.props` or the consuming project) — it then covers every package from this author. Pick one of the following.

#### Option 1 — Sponsor

Sponsor the author, then declare the account you sponsor under:

```xml
<!-- Owner mode: set once as a global property, in Directory.Build.props or the consuming .csproj -->
<PropertyGroup>
  <acme_GitHubSponsorAccount>your-account</acme_GitHubSponsorAccount>
</PropertyGroup>
```

Sponsor at https://github.com/sponsors/acmecorp

_Started sponsoring only recently?_ If your sponsorship began after this version was published, the bundled list cannot contain you yet — add `SponsorshipStart="yyyy-MM-dd"` alongside the account to attest to the start date until you upgrade to a later release.

#### Option 2 — Private license

If you have a private (B2B) licensing arrangement, set a time-bounded license. The value is `yyyy-MM` (the last covered month) and is valid through the end of that month (UTC). Values more than one year out are rejected, so renewal is a periodic one-line edit:

```xml
<!-- Owner mode: set once as a global property, in Directory.Build.props or the consuming .csproj -->
<PropertyGroup>
  <acme_SponsorshipLicensedUntil>yyyy-MM</acme_SponsorshipLicensedUntil>
</PropertyGroup>
```

#### Option 3 — Claim an exemption

The following exemptions are defined for this package. If one applies, claim it by name — the build passes with a warning quoting the exemption's criteria (not a breach message):

- `Consulting` — Consulting clients are exempt for 6 months.

```xml
<!-- Owner mode: set once as a global property, in Directory.Build.props or the consuming .csproj -->
<PropertyGroup>
  <acme_SponsorshipExemption>Consulting</acme_SponsorshipExemption>
</PropertyGroup>
```

#### Option 4 — Opt out

You can opt out of the check. The build stays green but logs a breach-of-license warning on every build.

```xml
<!-- Owner mode: set once as a global property, in Directory.Build.props or the consuming .csproj -->
<PropertyGroup>
  <acme_SponsorshipLicenseIgnored>true</acme_SponsorshipLicenseIgnored>
</PropertyGroup>
```
