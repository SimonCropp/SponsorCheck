    <pre class="code-box-content"><code>## Sponsorship is now checked at build time

`MyOssLib` 2.0.0 now bundles [SponsorCheck](https://github.com/SimonCropp/SponsorCheck) — a build-time check that asks teams using this package to sponsor its ongoing development. SponsorCheck adds **no runtime dependency**; the check runs only during the build.

After upgrading, every build looks for one of the options below. If none is configured the build fails with an error.

### What you need to do

Pick exactly one of the following and add it where the package is referenced (on the `&lt;PackageReference&gt;`, or on the `&lt;PackageVersion&gt;` in `Directory.Packages.props` if you use Central Package Management).

Prefer a guided setup? The [SponsorCheck setup wizard for `MyOssLib`](https://simoncropp.github.io/SponsorCheck/package/MyOssLib) reads this package's published configuration from nuget.org and generates the exact snippet and the file it belongs in.

#### Option 1 — Sponsor

Sponsor the author, then declare the account you sponsor under:

```xml
&lt;!-- Without Central Package Management: in the consuming .csproj --&gt;
&lt;PackageReference Include="MyOssLib" Version="2.0.0" GitHubSponsorAccount="your-account" /&gt;

&lt;!-- With Central Package Management: on the matching PackageVersion in Directory.Packages.props --&gt;
&lt;PackageVersion Include="MyOssLib" Version="2.0.0" GitHubSponsorAccount="your-account" /&gt;
```

Sponsor at https://github.com/sponsors/acmecorp

_Started sponsoring only recently?_ If your sponsorship began after this version was published, the bundled list cannot contain you yet — add `SponsorshipStart="yyyy-MM-dd"` alongside the account to attest to the start date until you upgrade to a later release.

#### Option 2 — Private license

If you have a private (B2B) licensing arrangement, set a time-bounded license. The value is `yyyy-MM` (the last covered month) and is valid through the end of that month (UTC). Values more than one year out are rejected, so renewal is a periodic one-line edit:

```xml
&lt;!-- Without Central Package Management: in the consuming .csproj --&gt;
&lt;PackageReference Include="MyOssLib" Version="2.0.0" SponsorshipLicensedUntil="yyyy-MM" /&gt;

&lt;!-- With Central Package Management: on the matching PackageVersion in Directory.Packages.props --&gt;
&lt;PackageVersion Include="MyOssLib" Version="2.0.0" SponsorshipLicensedUntil="yyyy-MM" /&gt;
```

#### Option 3 — Opt out

You can opt out of the check. The build stays green but logs a breach-of-license warning on every build.

```xml
&lt;!-- Without Central Package Management: in the consuming .csproj --&gt;
&lt;PackageReference Include="MyOssLib" Version="2.0.0" SponsorshipLicenseIgnored="true" /&gt;

&lt;!-- With Central Package Management: on the matching PackageVersion in Directory.Packages.props --&gt;
&lt;PackageVersion Include="MyOssLib" Version="2.0.0" SponsorshipLicenseIgnored="true" /&gt;
```

### Reference

Build diagnostics use `SC0xx` codes — see the [verifier diagnostic reference](https://github.com/SimonCropp/SponsorCheck/blob/main/docs/VerifierDiagnosticCodes.md).</code></pre></div></section>
