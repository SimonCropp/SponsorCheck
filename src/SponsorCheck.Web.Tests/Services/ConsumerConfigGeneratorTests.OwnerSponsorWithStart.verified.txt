=== Instruction ===
Add the properties below to a <PropertyGroup>. One declaration covers every package from owner 'acme'; the property names are exact (the owner prefix is baked into the package).

=== Build outcome ===
When 2026-04-30 is after the package version's pack date, the build passes and logs a high-priority SC017 audit message naming the unverified sponsor — the declaration is trusted because the bundled list cannot contain a sponsorship that began after it was frozen. A future date fails with SC028. The attestation self-expires: after upgrading to a version packed later than the start date, the normal bundled-list check applies again and SponsorshipStart can be dropped.

=== Notes ===
- The bundled list is frozen per package version: versions that pass keep passing even if sponsorship later lapses; a lapse surfaces when upgrading to a version packed after it.
- The properties cover every package from owner 'acme' — one declaration for the whole family. The exact property names are also printed in the SC021 error message.

# Configure SponsorCheck licensing for ThePackage

Generated by the [SponsorCheck setup wizard](https://simoncropp.github.io/SponsorCheck/consumer).

Context: the build references `ThePackage` 1.2.3, which bundles the [SponsorCheck](https://github.com/SimonCropp/SponsorCheck) build-time sponsorship verifier, and requires a license-mode declaration on every build.

- Chosen mode: sponsor account match
- Placement: owner mode — global MSBuild properties prefixed 'acme_'

## Change to make

File to edit: Directory.Build.props (covers every project under it) — or any one consuming project's .csproj.

Add the properties below to a <PropertyGroup>. One declaration covers every package from owner 'acme'; the property names are exact (the owner prefix is baked into the package).

```xml
<PropertyGroup>
  <acme_GitHubSponsorAccount>carol</acme_GitHubSponsorAccount>
  <acme_SponsorshipStart>2026-04-30</acme_SponsorshipStart>
</PropertyGroup>
```

## Expected build outcome

When 2026-04-30 is after the package version's pack date, the build passes and logs a high-priority SC017 audit message naming the unverified sponsor — the declaration is trusted because the bundled list cannot contain a sponsorship that began after it was frozen. A future date fails with SC028. The attestation self-expires: after upgrading to a version packed later than the start date, the normal bundled-list check applies again and SponsorshipStart can be dropped.

Notes:

- The bundled list is frozen per package version: versions that pass keep passing even if sponsorship later lapses; a lapse surfaces when upgrading to a version packed after it.
- The properties cover every package from owner 'acme' — one declaration for the whole family. The exact property names are also printed in the SC021 error message.
