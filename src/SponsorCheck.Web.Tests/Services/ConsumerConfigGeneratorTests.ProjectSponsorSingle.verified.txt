=== Build outcome ===

If the build still fails with SC007, either the account or platform doesn't match what the author bundled, the sponsorship began after this version was packed — in that case add SponsorshipStart="yyyy-MM-dd" — or the sponsorship is private (GitHub Sponsors) or incognito (Open Collective), which is never bundled and needs SponsorshipPrivateUntil="yyyy-MM" instead. Re-run the wizard and answer yes to whichever applies.

=== Notes ===

- If the solution adopts Central Package Management later, the metadata moves to the matching <PackageVersion> in Directory.Packages.props — wrong placement raises SC020, both places raises SC019.

# Configure SponsorCheck licensing for ThePackage

Generated by the [SponsorCheck setup wizard](https://simoncropp.github.io/SponsorCheck/consumer).

Context: the build references `ThePackage` 1.2.3, which bundles the [SponsorCheck](https://github.com/SimonCropp/SponsorCheck) build-time sponsorship verifier, and requires a license-mode declaration on every build.

- Chosen mode: sponsor account match
- Placement: per-package metadata on the <PackageReference> (no Central Package Management)

## Change to make

File to edit: The consuming project's .csproj — the file holding the <PackageReference> for 'ThePackage'.

Add the new attribute(s) to the existing <PackageReference Include="ThePackage"> element — do not create a second reference.

```xml
<PackageReference Include="ThePackage" Version="1.2.3"
                  GitHubSponsorAccount="alice" />
```

## Expected build outcome

Passes silently when any declared account was in the bundled sponsor list at the version's pack time. If the build still fails with SC007, either the account or platform doesn't match what the author bundled, the sponsorship began after this version was packed — in that case add SponsorshipStart="yyyy-MM-dd" — or the sponsorship is private (GitHub Sponsors) or incognito (Open Collective), which is never bundled and needs SponsorshipPrivateUntil="yyyy-MM" instead. Re-run the wizard and answer yes to whichever applies.

Notes:

- The bundled list is frozen per package version: versions that pass keep passing even if sponsorship later lapses; a lapse surfaces when upgrading to a version packed after it.
- If the solution adopts Central Package Management later, the metadata moves to the matching <PackageVersion> in Directory.Packages.props — wrong placement raises SC020, both places raises SC019.
