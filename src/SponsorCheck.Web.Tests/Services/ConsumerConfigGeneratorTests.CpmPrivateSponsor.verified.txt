=== Build outcome ===
Private (GitHub Sponsors) and incognito (Open Collective) sponsorships are deliberately excluded from the bundled hash list, so there is nothing for the verifier to match — the declaration is trusted instead. The build passes through the end of 2027-05 (UTC) and logs a high-priority SC059 audit message naming the account and the end month. After that it fails with SC057 until the claim is renewed, which is the point: a private sponsorship that quietly lapsed should stop working rather than ride along forever. The publisher caps the claim (the default is 12 months, and this package could not be inspected to confirm), so a month further out fails with SC054. A value that isn't 'yyyy-MM' fails with SC051.

=== Notes ===
- The bundled list is frozen per package version: versions that pass keep passing even if sponsorship later lapses; a lapse surfaces when upgrading to a version packed after it.
- Keep the metadata in exactly one place: on the <PackageVersion>. Setting it on the <PackageReference> as well raises SC019; only on the <PackageReference> raises SC020.

# Configure SponsorCheck licensing for ThePackage

Generated by the [SponsorCheck setup wizard](https://simoncropp.github.io/SponsorCheck/consumer).

Context: the build references `ThePackage` 1.2.3, which bundles the [SponsorCheck](https://github.com/SimonCropp/SponsorCheck) build-time sponsorship verifier, and requires a license-mode declaration on every build.

- Chosen mode: sponsor account match
- Placement: per-package metadata on the <PackageVersion> (Central Package Management)

## Change to make

File to edit: Directory.Packages.props — the file holding the <PackageVersion> items under Central Package Management.

Add the new attribute(s) to the existing <PackageVersion Include="ThePackage"> element — do not create a second element, and do not put the metadata on the <PackageReference>.

```xml
<PackageVersion Include="ThePackage" Version="1.2.3"
                OpenCollectiveSponsorAccount="octocat"
                SponsorshipPrivateUntil="2027-05" />
```

## Expected build outcome

Private (GitHub Sponsors) and incognito (Open Collective) sponsorships are deliberately excluded from the bundled hash list, so there is nothing for the verifier to match — the declaration is trusted instead. The build passes through the end of 2027-05 (UTC) and logs a high-priority SC059 audit message naming the account and the end month. After that it fails with SC057 until the claim is renewed, which is the point: a private sponsorship that quietly lapsed should stop working rather than ride along forever. The publisher caps the claim (the default is 12 months, and this package could not be inspected to confirm), so a month further out fails with SC054. A value that isn't 'yyyy-MM' fails with SC051.

Notes:

- The bundled list is frozen per package version: versions that pass keep passing even if sponsorship later lapses; a lapse surfaces when upgrading to a version packed after it.
- Keep the metadata in exactly one place: on the <PackageVersion>. Setting it on the <PackageReference> as well raises SC019; only on the <PackageReference> raises SC020.
