- Package facts (read from the published nupkg): version 1.2.3, packed 2026-01-15, transitive checking off

File to edit: The consuming project's .csproj — the file holding the <PackageReference> for 'ThePackage'.

Add the new attribute(s) to the existing <PackageReference Include="ThePackage"> element — do not create a second reference.

```xml
<PackageReference Include="ThePackage" Version="1.2.3"
                  GitHubSponsorAccount="carol"
                  SponsorshipStart="2026-01-10" />
```

## Expected build outcome

The declared start (2026-01-10) is on or before this version's pack date (2026-01-15) — the boundary is strict, so the attestation does NOT bypass the check. The normal bundled-list check applies: the account must have been in the list at pack time, or the build fails with SC007. Re-check the actual start date, or drop SponsorshipStart.

Notes:

- The bundled list is frozen per package version: versions that pass keep passing even if sponsorship later lapses; a lapse surfaces when upgrading to a version packed after it.
- If the solution adopts Central Package Management later, the metadata moves to the matching <PackageVersion> in Directory.Packages.props — wrong placement raises SC020, both places raises SC019.
